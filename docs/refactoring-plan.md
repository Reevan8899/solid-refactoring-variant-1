# План рефакторинга

**Вариант 1. Обработка заказов.** Самостоятельный учебный исходник подготовлен по варианту задания. Зафиксирована публичная точка входа `order_processor.OrderProcessor`, результаты, схема SQLite и видимые побочные эффекты.

| Принцип | Нарушение в исходнике | Изменение | Проверка |
|---|---|---|---|
| SRP | `OrderProcessor` содержит валидацию, расчёт, SQL, уведомления, журнал и PDF. | Вынести эти обязанности в отдельные компоненты. | Те же характеризующие тесты и сравнение длины методов. |
| OCP | Скидки выбираются через `if/elif` в калькуляторе. | Подключать стратегии через реестр фабрики. | Добавить тестовую стратегию без правки калькулятора. |
| LSP | `PremiumUser.get_email()` возвращает словарь при контракте `str`. | Ввести контракт получателя, общую реализацию email и специализированную тему письма. | Проверить один уведомитель с обычным и premium-получателем. |
| ISP | Просмотр реализует ненужные методы большого интерфейса. | Разделить чтение, запись, уведомление, аудит и генерацию счёта. | Проверить просмотр с объектом, который поддерживает только чтение. |
| DIP | Процессор напрямую создаёт конкретную БД и побочные эффекты. | Передавать зависимости через конструктор сервиса. Сборку SQLite оставить в точке входа. | Проверить сервис с хранилищем в памяти и тестовыми адаптерами. |

Сначала измеряется базовая версия. Каждый принцип применяется отдельным коммитом. На каждом шаге запускается `tests_before`. Цели для финальной версии — покрытие не ниже 85%, средняя сложность не выше 10, индекс поддерживаемости каждого измеряемого модуля не ниже 60.
